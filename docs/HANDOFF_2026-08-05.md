## 4. Full narrative of what happened, in order

### 4.1 Stage 1: FactSet extraction (built, tested against real server)

- Discovered (by reading the user's Windows machine, read-only) that the FactSet
  feed is **Microsoft SQL Server**, self-managed on **AWS ap-south-1 (Mumbai)
  EC2**, SQL auth, database `fds_datafeeds`. NOT Snowflake/BigQuery as initially
  guessed from FactSet table names.
- Built a full design doc (`docs/DATABASE_DESIGN.md`, ~68KB) covering: universe-
  first extraction pattern (resolve ~30k securities first, THEN join the 1B-row
  price table — turns a 121GB scan into 2.65GB on the wire, ~45x), server-side
  CAST narrowing (TDS has NO wire compression, unlike a warehouse), sharding on
  `fsym_id` ranges (the clustered PK on `fp_basic_prices` is `(fsym_id, p_date)`,
  confirmed via live discovery), manifest-based resumability (sha256 + query_hash
  + universe_hash per shard), the Parquet compression arithmetic, and a 27-row
  "naive approach / why it loses" decision table (this table is the single most
  reused artifact in the whole project — promoted into the README).
- **Live discovery session** against the real server (read-only SQL) resolved
  every open question: OHLC columns exist in `fp_basic_prices`; split factor
  convention pinned against 5 real AAPL splits (`p_split_factor` is the
  **reciprocal** of the ratio — a 4-for-1 is stored as 0.25, multiply pre-split
  prices by it); adjustment factors live in `fgp_v1.fgp_ca_adj_factors` with TWO
  columns (`adj_factor_combined` = splits only/price-return,
  `div_spl_spin_adj_factor` = splits+divs/total-return); volume is in
  **fractional thousands** (not raw shares — corrected an earlier wrong
  assumption); `rbics_v1` (point-in-time sector) is **completely empty** in this
  feed (also corrected an earlier wrong assumption); no CRSP-style delisting
  return exists (only 374 liquidation records globally) — **CRSP stays required**
  for that field; real US exchange codes are `NYS, NAS, ASE, PSE` (NOT `ARC/BAT/
  IEX` as first guessed — those are trading venues, never listing exchanges).
  Full findings: `docs/DISCOVERY_FINDINGS.md`.
- **Ran the real extraction** against the live server: 39,677,253 rows, 16,367
  securities, 1995–2026, in 9.3 minutes (~85k rows/s once warmed up — initial
  estimate of 30-40 min was 4x pessimistic). Reconciled row-for-row against a
  server-authored oracle (exact integer checksums) for **all 32 years, zero
  mismatches**.
- Extraction code lives at `src/statarb/ingest/factset/`: `config.py` (env-driven,
  NO hardcoded host/user/password), `queries.py` (all SQL, parameterized),
  `extractor.py` (arrow-odbc streaming, manifest, retry logic), `verify.py`
  (oracle reconciliation), `extract_raw_factset.py` (CLI entry), `run_discovery.py`
  (the 27 discovery queries).
- **Universe decision:** all US-listed common stock (`SHARE` type, `p_sec_type_code
  ='10'`), NYS/NAS/ASE/PSE only, **OTC deliberately excluded** (would ~triple the
  universe with unborrowable/unshortable names — user's call, recorded as a
  decision). **No `active_flag` filter ever** — this is the core survivorship-bias
  guard. Measured result: **68.6% of the 16,367-security universe is dead**
  (delisted/acquired/bankrupt) as of now. This number is the headline stat in the
  README.
- History window: **1995–2026** (not 2000 as first discussed) — deliberate,
  because it's a one-shot office extraction and the extra 5 years cost ~50 extra
  seconds of transfer.

### 4.2 Stage 2: curated Delta Lake + DataAPI (built, tested, verified against real data)

- `src/statarb/curate/factors.py` — the **cumulative adjustment factor
  arithmetic**. This is the most rigorously tested module in the repo (17 unit
  tests + real-data validation). Core algorithm: per-event factors (splits,
  dividends) become a cumulative factor via a **reverse running product** —
  `cum_factor(t) = product of every event factor with effective_date > t`
  (**strict** `>`, not `>=` — the effective date itself is already in post-event
  terms in the vendor data). Validated against real AAPL data: the 2020-08-31
  4-for-1 split reads as **+3.39%** adjusted (was -74.15% raw). This exact
  number (`+3.39%` vs `-74.15%`) is quoted throughout the docs/README as the
  canonical proof-of-correctness — reproduce it whenever verifying nothing broke.
- Design decision (user's): **store raw price + cumulative factor, compute
  adjusted price ON READ, never store adjusted prices.** Rationale: a future
  split only changes the factor column; adjusted-price columns would otherwise
  go silently stale.
- `src/statarb/curate/schema.py` — explicit pyarrow schemas, Delta retention
  properties set to **10 years** (Delta's default is 7-day file retention / 30-day
  log retention — would silently expire the ability to time-travel).
- `src/statarb/curate/build.py` — raw Parquet → curated Delta tables (prices,
  dim_security, corporate_actions, calendar). Runs in ~30s for the full dataset.
  Compacts 1,312 small files down to 32 via `dt.optimize.z_order(["sid"])`.
- `src/statarb/data/api.py` — **`DataAPI`**, the single read interface. Key
  methods: `get_prices(sids, start, end, adjusted="raw"|"price"|"total")`,
  `get_returns`, `get_panel` (wide format for PCA), `get_universe_as_of(date,
  min_price=, min_adv_usd=)` — **the point-in-time guarantee**: never filters on
  `is_dead`/`active_flag`, liquidity screens use only trailing data ending at
  the as-of date. `get_trading_days`/`get_rebalance_dates` from FactSet's own
  calendar (not derived from one stock's price index, which was the legacy bug).
  `sid_for_ticker` raises `KeyError` on ambiguous/reused tickers rather than
  guessing. `DataAPI(root=..., version=...)` — explicit root (never touches env
  at call time) and Delta version pinning for exact reproducibility.
- Two real bugs found and fixed during this build, both caught by testing against
  real data rather than assumed correct:
  1. `is_primary_class` compared the wrong ID namespace (`fsym_regional_id` vs
     `fsym_primary_equity_id`, which is actually a `-S` security id, not `-R`) —
     silently reported ALL securities as non-primary. Fixed in `curate/build.py`.
  2. `n_classes_in_entity` used `.over("factset_entity_id")` with no NULL guard —
     Polars treats all NULLs as one group, so ~317 unrelated securities all
     reported `n_classes_in_entity=317`. Fixed with an explicit `pl.when(...
     is_null())` branch.

## 6. Key technical facts to carry forward (don't re-derive these)

- **FactSet transport:** MS SQL Server, AWS ap-south-1, office-network-only.
  Credentials in `.env` (`FACTSET_SQL_SERVER`, `FACTSET_SQL_DATABASE`,
  `FACTSET_SQL_USER`, `FACTSET_SQL_PASSWORD` — leave unset for getpass prompt).
- **Universe:** 16,367 US common-stock securities, NYS/NAS/ASE/PSE, 1995–2026.
  68.6% dead. `sid` is an `int32` surrogate key, permanent, append-only, never
  renumbered.
- **Price fact table:** 39,677,253 rows, sharded by `sid` range (41 shards) —
  the clustered PK on `fp_basic_prices` is `(fsym_id, p_date)`, confirmed live,
  so sid-range sharding is a clustered SEEK not a scan, and rows arrive already
  sorted (no external sort needed downstream).
- **Adjustment factor convention (empirically verified against 5 real AAPL
  splits):** `p_split_factor` is `1/ratio`. Multiply pre-event prices by the
  cumulative product of all LATER event factors (strict `>` on effective_date).
- **Two adjustment series:** `cum_px_factor` (splits/spinoffs only — price
  return) and `cum_tr_factor` (splits+dividends — total return), both float64
  (never narrow — they're running products, error compounds).
- **Prices stored `float32`** (source is 4-decimal, float32 has ~7 sig figs —
  no real loss). **Volume stored `int64`** (NOT float32 — would silently corrupt
  above 2^24=16.7M shares; source data is fractional thousands, `round(v*1000)`
  gives ±1000-share accuracy).
- **Delta retention = 10 years** (`schema.DELTA_PROPERTIES`) — the 7-day/30-day
  defaults would silently expire time-travel.
- **No delisting return exists in FactSet** (only 374 liquidation records
  globally vs thousands of real US delistings) — CRSP remains required for that
  one field. This is a permanent, accepted limitation, not a bug to fix here.
- **Sector data (`rbics_v1`) is EMPTY** in this feed — no point-in-time sector
  classification is possible from FactSet alone. Design response: cluster on
  statistical factor loadings (PCA) rather than vendor sector labels, which
  removes the dependency rather than working around it. This affects how
  Stage 3 clustering should be designed.
- **OTC exchange deliberately excluded** from the universe (would ~triple it
  with unshortable/unborrowable names) — `OTC_EXCHANGE_CODES = ()` in config,
  user's explicit call.
- **`config.py` design pattern to preserve:** connection settings (`SERVER_NAME`,
  `DATABASE`, `USER_NAME`) have empty-string defaults at MODULE level (so
  importing never crashes) but are validated via
  `require_connection_config()` called only at actual connect time. This exact
  pattern (lazy validation, not lazy import) is what makes the package importable
  in CI with zero credentials — don't "fix" this by adding `required=True` at
  module scope, that reintroduces the original `settings.py` bug.
- **Python 3.14.6** is the installed interpreter and it WORKS — `pyarrow`,
  `arrow-odbc`, `deltalake`, `polars` all had cp314 wheels. No need to pin 3.13
  despite `pyproject.toml`'s `requires-python = ">=3.13"` (that floor is for CI
  matrix breadth, not because 3.14 doesn't work locally).
- **`sklearn`/`statsmodels`/`scipy` had to be installed** into `.venv` during
  the cleanup (`pip install --only-binary :all: scikit-learn statsmodels scipy`)
  — they weren't there before, needed for the legacy `research/` modules to
  import. Confirm they're still present in a new session (`pip list` or just try
